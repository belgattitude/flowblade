`@flowblade/source-kysely` wraps an existing [Kysely](https://kysely.dev/)
instance and provides Flowblade's result, error, metadata, streaming and
transaction APIs. Use your existing Kysely dialect, driver and database
configuration.

## Install

```bash
npm install @flowblade/source-kysely kysely
```

Install the driver and dialect dependencies required by your database. The
optional `createKyselyMssqlDialect()` helper for SQL Server and Azure SQL Edge
also requires `tedious` and `tarn`.

## Quick start

```typescript
import { KyselyDatasource } from "@flowblade/source-kysely";
import { db } from "./db.js"; // Your configured Kysely<DB> instance

const ds = new KyselyDatasource({ connection: db });

const query = ds.queryBuilder
  .selectFrom("person")
  .select(["id", "name"])
  .where("active", "=", true);

const result = await ds.query(query, { name: "listActivePeople" });

if (result.error) {
  console.error(result.error.code, result.error.message, result.error.cause);
} else {
  console.log(result.data);
}

// Or use exception-based control flow:
const { data: people, meta } = await ds.queryOrThrow(query);
console.log(`${people.length} rows in ${meta.getTotalTimeMs()}ms`);
```

The `queryBuilder` getter provides the Kysely query builder. The datasource
accepts compiled Kysely queries and raw Kysely query builders.

## Query methods and results

`query()` and `queryOne()` return `QResult` and do not throw. Their `OrThrow`
counterparts return data directly and throw typed errors. `queryOne()` returns
`null` when no row matches and reports `TOO_MANY_RESULTS` for multiple rows.
`queryOneOrThrow()` throws `QErrors.NoResult` for no row unless `defaultValue`
is set.

One-row methods do not add `LIMIT` or otherwise rewrite SQL. All matching rows
are fetched before checking the count, so bound non-unique queries yourself
with `.limit(2)` (or `.top(2)` for SQL Server).

`QResult` contains either `data` or `error`, plus `meta`. Driver errors are
available as `error.cause` but omitted by `toJsonifiable()`. See
[Flowblade core](/docs/core) for the shared error codes, HTTP status suggestions,
metadata and error-factory options.

## Streaming

`stream()` yields individual rows rather than loading the full result into
memory. `chunkSize` is used only by dialects that support it.

```typescript
const rows = ds.stream(
  ds.queryBuilder.selectFrom("person").select(["id", "name"]),
  { name: "streamPeople", chunkSize: 500 }
);

for await (const row of rows) {
  console.log(row.name);
  if (row.name === "Stop here") {
    break;
  }
}
```

Breaking early releases the database connection and invalidates the stream.
Errors are thrown during iteration as `QErrors.QueryFailed` or
`QErrors.Aborted`.

## Errors and cancellation

`query()` returns `QUERY_FAILED` for execution/compilation errors and `ABORTED`
for aborted work. Throwing methods expose `QErrors.QueryFailed`,
`QErrors.Aborted`, `QErrors.NoResult` and `QErrors.TooManyResults`. Use the
`onError`, `onNoResult` and `onTooManyResults` factories to map them to
application-specific errors; factories can also be set in `defaultOptions`.

Query methods and streams accept an `AbortSignal`:

```typescript
const result = await ds.query(query, {
  signal: AbortSignal.timeout(5_000),
});
```

By default, Kysely may stop waiting while the database query continues to run.
Set `inflightQueryAbortStrategy` to `"cancel query"` or `"kill session"` to
request cancellation when the dialect supports it. Unsupported cancellation
falls back to ignoring the in-flight query, with a warning. A datasource-wide
default is configured under `defaultOptions.query`; it can also be set per
query.

## Transactions and savepoints

`transaction()` returns a result; `transactionOrThrow()` throws. Both pass a
transaction-scoped datasource to the callback. Use and await `tx` queries in
the callback, not the outer datasource. Nested transactions are not supported.

```typescript
const { data: newId } = await ds.transactionOrThrow(
  async (tx) => {
    const { data: person } = await tx.queryOneOrThrow(
      tx.queryBuilder
        .insertInto("person")
        .values({ name: "Ada", active: true })
        .returning("id")
    );
    return person.id;
  },
  {
    name: "createPerson",
    isolationLevel: "serializable",
    retry: { maxRetries: 3 },
  }
);
```

Transaction options include `isolationLevel`, `accessMode`, `signal`,
`retry` and `onFailedQuery`. Database support varies. Conflicts such as
serialization failures and deadlocks are recognized for Postgres, SQL Server
and MySQL; configure `isTransactionConflict` for other drivers. Retries are
opt-in, use exponential backoff with jitter, and call the callback again.
Keep external side effects outside retried callbacks.

Failed queries roll back the transaction by default, even if the callback
handles the returned error. `onFailedQuery: "commit"` can be used only when
the database does not automatically abort the transaction for that statement;
do not use it with Postgres. Prefer savepoints to recover from a failed query
inside a transaction.

`tx.savepoint()` and `tx.savepointOrThrow()` isolate a callback's work and can
be nested. They are useful for handling expected statement failures (for
example, a duplicate insert) without rolling back the whole transaction.
Savepoint support depends on the Kysely dialect.

See [core transaction semantics](/docs/core#transactions) for error states,
retry defaults, metadata and general guidance.

## SQL Server and Azure SQL Edge

`createKyselyMssqlDialect()` builds a Kysely dialect using `tedious`. It accepts
`tediousConfig`, optional `tarn` `poolOptions`, and `dialectConfig`. The
`validateConnections` and `resetConnectionsOnRelease` options add validation
or reset roundtrips when enabled; disabling them can improve performance when
appropriate for your deployment.

```typescript
import * as Tedious from "tedious";
import {
  createKyselyMssqlDialect,
  TediousConnUtils,
} from "@flowblade/source-kysely";

const tediousConfig = TediousConnUtils.fromJdbcDsn(
  process.env.DB_JDBC_DSN
);
const dialect = createKyselyMssqlDialect({
  tediousConfig,
  poolOptions: { min: 0, max: 10 },
  dialectConfig: {
    validateConnections: true,
    resetConnectionsOnRelease: false,
    tediousTypes: {
      ...Tedious.TYPES,
      NVarChar: Tedious.TYPES.VarChar,
      DateTime: Tedious.TYPES.DateTime2,
    },
  },
});
```

`TediousConnUtils.fromJdbcDsn()` parses and validates a JDBC-style SQL Server
connection string. Pool and dialect options are specific to this helper; for
other databases, configure the Kysely dialect as usual.

## Logging and lifecycle

The adapter logs through LogTape in the `["flowblade", "kysely"]` category.
Configure LogTape in your application to enable output. Query logs include SQL
and, by default, bound parameters. Use `logParams: false` to keep parameters
out of logs; they remain available in result metadata. You may also supply a
custom `logger`.

The datasource uses the supplied Kysely instance; it does not own it or manage
application shutdown. Close the Kysely instance when the application stops:

```typescript
await db.destroy();
```
